Trilha de games — Unity com C#

Unity é a engine mais usada do mundo e programa-se em C#. Aqui você sai do console e entra no jogo: script de componente, física, UI e build. Faça os fundamentos (pelo menos até o módulo 12) antes.

Para praticar: instale o Unity Hub e crie um projeto 2D. No Linux Mint ele roda nativamente (build com suporte a Linux e Windows).

G1

Seu primeiro MonoBehaviour

GameObject · Component · Start/Update · Time.deltaTime

No Unity tudo é GameObject (o objeto na cena) com Componentes pendurados nele (transform, renderer, script). Um script C# que herda de MonoBehaviour vira um componente: você arrasta no objeto e ele passa a rodar os métodos de ciclo de vida.

using UnityEngine;

public class MovimentoJogador : MonoBehaviour
{
    [SerializeField] private float velocidade = 6f;   // aparece no Inspector
    [SerializeField] private float forcaPulo = 8f;

    private Rigidbody2D corpo;

    // roda uma vez, antes do primeiro Update
    private void Awake()
    {
        corpo = GetComponent<Rigidbody2D>();
    }

    // roda uma vez, no primeiro frame (depois dos Awake de todos)
    private void Start()
    {
        Debug.Log("Jogador em campo!");
    }

    // roda a cada frame: leitura de input
    private void Update()
    {
        float horizontal = Input.GetAxisRaw("Horizontal");

        // deltaTime deixa o movimento independente do FPS
        transform.Translate(Vector3.right * horizontal * velocidade * Time.deltaTime);

        if (Input.GetButtonDown("Jump"))
            corpo.AddForce(Vector2.up * forcaPulo, ForceMode2D.Impulse);
    }

    // roda em intervalo fixo: física
    private void FixedUpdate()
    {
        // velocidade constante, sem depender do frame
        corpo.linearVelocity = new Vector2(corpo.linearVelocity.x, corpo.linearVelocity.y);
    }
}
  • Ciclo de vida: Awake → OnEnable → Start → Update (todo frame) → FixedUpdate (física) → OnDisable → OnDestroy.
  • [SerializeField] mostra a variável no Inspector sem deixá-la pública.
  • Multiplique movimento por Time.deltaTime; sem isso o jogo fica rápido em máquina boa e lento em máquina fraca.
  • Input fica no Update; física fica no FixedUpdate.
  • Debug.Log escreve no Console do editor — seu Console.WriteLine do jogo.

G2

Física, colisão e coleta de itens

Rigidbody2D · Collider2D · Tag · OnTriggerEnter2D

Colisão precisa de duas peças: um Collider (a forma) e, se o objeto se move, um Rigidbody (a massa que a física controla). Sem Rigidbody, o Unity só detecta o toque, não empurra.

using UnityEngine;

public class Coletavel : MonoBehaviour
{
    [SerializeField] private int valor = 1;
    [SerializeField] private AudioClip somMoeda;

    private void OnTriggerEnter2D(Collider2D outro)
    {
        // só reage ao jogador
        if (!outro.CompareTag("Player")) return;

        var placar = outro.GetComponent<Placar>();
        if (placar != null)
            placar.Adicionar(valor);

        if (somMoeda != null)
            AudioSource.PlayClipAtPoint(somMoeda, transform.position, 0.7f);

        Destroy(gameObject);   // remove o item da cena
    }
}

public class Placar : MonoBehaviour
{
    [SerializeField] private int pontos;

    public void Adicionar(int valor)
    {
        pontos += valor;
        Debug.Log($"Pontos: {pontos}");

        if (pontos >= 100)
            Debug.Log("Fim de jogo: vitória!");
    }
}
  • OnCollisionEnter2D = batida com resposta física; OnTriggerEnter2D = atravessa e só dispara evento (marque Is Trigger).
  • Tags evitam comparações frágeis de nome e são mais rápidas que name == "...".
  • GetComponent<T>() busca componente no mesmo objeto; GetComponentInChildren desce a hierarquia.
  • Destroy(gameObject) destrói o objeto inteiro; Destroy(this) remove só o componente.
  • Para empurrar de verdade, mova via Rigidbody2D (AddForce, linearVelocity), não via transform.position.

G3

UI, prefabs e ScriptableObject

Canvas · TextMeshPro · Instantiate · dados em asset

Jogo não é só a cena: você precisa mostrar HUD, repetir objetos (prefabs) e guardar configurações de dados fora do código (ScriptableObject).

using TMPro;
using UnityEngine;

public class HudJogo : MonoBehaviour
{
    [SerializeField] private TextMeshProUGUI textoPlacar;
    [SerializeField] private GameObject prefabBola;
    [SerializeField] private Transform pontoDeSaida;

    private int gols;

    public void RegistrarGol()
    {
        gols++;
        textoPlacar.text = $\"Corinthians {gols}\";

        // instancia uma cópia do prefab na cena
        var bola = Instantiate(prefabBola, pontoDeSaida.position, Quaternion.identity);
        Destroy(bola, 5f);   // limpa depois de 5 segundos
    }
}

// ScriptableObject: dado que vive fora da cena, editável no Inspector
[CreateAssetMenu(fileName = \"Jogador\", menuName = \"Timao/Jogador\")]
public class DadosJogador : ScriptableObject
{
    public string nome;
    public int camisa;
    public float velocidade = 5f;
    public int forca = 70;
}

// usável em qualquer cena, sem duplicar valores no código
public class AplicarDados : MonoBehaviour
{
    [SerializeField] private DadosJogador dados;

    private void Start()
    {
        name = dados.nome;
        Debug.Log($\"#{dados.camisa} {dados.nome} — força {dados.forca}\");
    }
}
  • Prefab é um modelo salvo: Instantiate cria cópias em tempo de execução.
  • ScriptableObject é um asset de dados: ideal para fichas de jogador, itens e balanceamento, e é compartilhado entre cenas sem recarregar.
  • UI no Unity usa Canvas; textos modernos usam TextMeshPro (TMPro).
  • Destroy(obj, 5f) agenda a destruição — bom para efeitos temporários.
  • Quaternion.identity significa "sem rotação".

G4

Build, performance e roteiro

IL2CPP · Profiler · object pooling · próximo passo

Build no Unity é escolher plataforma (PC/Linux/Android/Web), script backend e qualidade gráfica. Para um jogo 2D leve, um build Linux com IL2CPP costuma abrir em qualquer notebook.

// PROBLEMA: criar e destruir objetos a cada tiro gera lixo de memória
void AtirarRuim() => Instantiate(balaPrefab, cano.position, cano.rotation);

// SOLUÇÃO: object pooling — reaproveita uma pilha de objetos
public class PoolBalas : MonoBehaviour
{
    [SerializeField] private GameObject prefab;
    [SerializeField] private int tamanho = 20;

    private readonly Queue<GameObject> livres = new();

    private void Awake()
    {
        for (int i = 0; i < tamanho; i++)
        {
            var b = Instantiate(prefab, transform);
            b.SetActive(false);
            livres.Enqueue(b);
        }
    }

    public GameObject Pegar(Vector3 posicao)
    {
        if (livres.Count == 0) return null;
        var b = livres.Dequeue();
        b.transform.position = posicao;
        b.SetActive(true);
        return b;
    }

    public void Devolver(GameObject b)
    {
        b.SetActive(false);
        livres.Enqueue(b);
    }
}
  • Profiler (Window → Analysis → Profiler) mostra onde o frame está sendo gasto antes de você otimizar no escuro.
  • Object pooling troca Instantiate/Destroy por ativar/desativar: menos GC, frame estável.
  • Build Settings → Player Settings: escolha IL2CPP para releases (mais rápido) e Mono para builds de teste rápidos.
  • Rode o build na máquina mais fraca que você tiver: é lá que os problemas aparecem.
  • Roteiro: faça um jogo pequeno e termine. Um clone de Pong com placar e menu ensina mais que dez protótipos abandonados.
