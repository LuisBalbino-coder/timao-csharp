D1

Scripts de console e agendamento

args · exit code · Directory · cron/systemd

Antes de app bonito, o programador precisa de ferramenta chata que funciona: renomear arquivos, juntar planilhas, gerar relatório. Um script de console em C# faz isso com a mesma linguagem do resto do projeto.

using System.Text.Json;

// args já vem pronto no top-level statements
if (args.Length < 2)
{
    Console.WriteLine("uso: relatorio <pasta> <saida.json>");
    return 1;                       // exit code != 0 sinaliza falha
}

string origem = args[0];
string destino = args[1];

try
{
    var arquivos = Directory
        .EnumerateFiles(origem, "*.log", SearchOption.AllDirectories)
        .Select(Path.GetFileName)
        .OrderBy(n => n)
        .ToList();

    long tamanhoTotal = Directory
        .EnumerateFiles(origem, "*", SearchOption.AllDirectories)
        .Sum(f => new FileInfo(f).Length);

    var relatorio = new
    {
        Gerado = DateTime.Now,
        Pasta = origem,
        Logs = arquivos.Count,
        TamanhoMB = Math.Round(tamanhoTotal / 1024d / 1024d, 2),
        Arquivos = arquivos
    };

    File.WriteAllText(destino, JsonSerializer.Serialize(relatorio,
        new JsonSerializerOptions { WriteIndented = true }));

    Console.WriteLine($"OK: {arquivos.Count} logs em {destino}");
    return 0;
}
catch (UnauthorizedAccessException ex)
{
    Console.Error.WriteLine($"Sem permissão: {ex.Message}");
    return 2;
}
catch (IOException ex)
{
    Console.Error.WriteLine($"Erro de disco: {ex.Message}");
    return 3;
}
  • Exit code 0 = sucesso; qualquer outro valor = falha (essencial para automação e CI).
  • Path, Directory e File cobrem quase todo trabalho com arquivos.
  • No Linux, agende com cron (crontab -e) ou um systemd timer rodando dotnet /caminho/app.dll.
  • Escreva erros em Console.Error e resultados em Console.Out: assim o script pode ser usado em pipe.
  • Publicar como executável único: dotnet publish -c Release -r linux-x64 --self-contained.

D2

Aplicativos desktop com Avalonia

XAML · MVVM · binding · comandos

Avalonia é a opção multiplataforma (Linux, Windows, macOS) mais parecida com o WPF do Windows. A ideia do MVVM: a tela (View) só desenha; a lógica fica na ViewModel, que não sabe nada de botão.

// MainWindow.axaml — a tela
<Window xmlns="https://github.com/avaloniaui"
        Title="Timão C#" Width="420" Height="320">
  <StackPanel Margin="20" Spacing="12">
    <TextBlock Text="{Binding Placar}" FontSize="26" />
    <TextBox Text="{Binding NomeGoleador}" Watermark="quem marcou?" />
    <Button Content="Registrar gol" Command="{Binding RegistrarGol}" />
    <TextBlock Text="{Binding Historico}" />
  </StackPanel>
</Window>

// MainWindowViewModel.cs — a lógica
using CommunityToolkit.Mvvm.ComponentModel;
using CommunityToolkit.Mvvm.Input;

public partial class MainWindowViewModel : ObservableObject
{
    [ObservableProperty] private int gols;
    [ObservableProperty] private string nomeGoleador = "";
    [ObservableProperty] private string historico = "";

    public string Placar => $"Corinthians {Gols}";

    [RelayCommand]
    private void RegistrarGol()
    {
        Gols++;
        OnPropertyChanged(nameof(Placar));
        Historico = $"{NomeGoleador} marcou ({Gols})";
    }
}
  • {Binding ...} liga um controle da tela a uma propriedade da ViewModel.
  • Para a tela atualizar sozinha, a ViewModel implementa INotifyPropertyChanged — o toolkit gera isso com [ObservableProperty].
  • [RelayCommand] transforma um método em Command para o botão.
  • A ViewModel é testável sem abrir janela: essa é a grande vantagem do padrão.
  • dotnet new install Avalonia.Templates e depois dotnet new avalonia.mvvm.

Integrações, dados e nuvem

HttpClient · CSV · Azure Functions · ML.NET

O que faz um programa ser útil é conversar com o mundo: consumir uma API de resultados, ler CSV de sócios, chamar um serviço de nuvem. Tudo isso é C# básico mais bibliotecas.

using System.Net.Http.Json;
using System.Globalization;

// ---------- consumir uma API pública ----------
var http = new HttpClient { BaseAddress = new Uri("https://api.exemplo.com/") };
var tabela = await http.GetFromJsonAsync<List<Time>>("classificacao");

foreach (var t in tabela ?? [])
    Console.WriteLine($"{t.Nome}: {t.Pontos}");

// ---------- ler CSV (planilha de sócios) ----------
var socios = File.ReadLines("socios.csv")
    .Skip(1)                                  // pula o cabeçalho
    .Select(linha => linha.Split(','))
    .Select(col => new
    {
        Nome  = col[0],
        Desde = DateTime.ParseExact(col[1], "dd/MM/yyyy", CultureInfo.InvariantCulture)
    })
    .Where(s => s.Desde.Year < 2020)
    .ToList();

Console.WriteLine($"{socios.Count} sócios antigos");

public record Time(string Nome, int Pontos, int Saldo);
  • GetFromJsonAsync / PostAsJsonAsync resolvem a maioria das chamadas HTTP.
  • Uma única instância de HttpClient reutilizada evita esgotar conexões; em apps grandes, use IHttpClientFactory.
  • CSV se lê linha a linha; para planilhas .xlsx use a biblioteca ClosedXML.
  • Azure Functions/AWS Lambda rodam C# como função serverless — código que só executa quando é chamado.
  • ML.NET e ONNX Runtime treinam/executam modelos de IA em C#; MAUI faz apps mobile; .NET nanoFramework chega a placas IoT.
