01

Olá, Timão — seu primeiro programa

estrutura · Console · interpolação · como o C# roda

Todo programa C# vive dentro de uma classe e começa no método Main. Desde o C# 9 existe o formato top-level statements: você escreve as instruções soltas no arquivo e o compilador gera a classe e o Main para você. É o formato dos exemplos deste site.

// Programa.cs — o arquivo mais simples que existe
Console.WriteLine("Vai, Timão!");
Console.WriteLine("Aprender C# é igual subir a Vila: no começo cansa.");

int gols = 3;
Console.WriteLine($"Placar: Corinthians {gols} x 0");

// O mesmo programa no formato "clássico", com classe e Main:
class Programa
{
    static void Main()
    {
        Console.WriteLine("Também funciona assim.");
    }
}
  • Console.WriteLine escreve uma linha no terminal; Console.Write não pula linha.
  • O $ antes das aspas liga a interpolação: {gols} vira o valor da variável.
  • Cada instrução termina em ;. Esquecer o ponto e vírgula é o erro nº 1 de quem começa.
  • // é comentário de linha; /* ... */ comenta um bloco.
  • O C# não é interpretado direto: ele compila para IL (uma linguagem intermediária) e o CLR executa com JIT em tempo de execução. Por isso é rápido e ainda assim portátil.

Para rodar de verdade: instale o .NET SDK, crie o projeto com dotnet new console -o Timao e execute dotnet run dentro da pasta. O arquivo gerado é o Program.cs.

02

Variáveis, tipos e conversões

int · double · decimal · string · bool · var · parse

Cada informação tem um tipo, e o tipo decide o que você pode fazer com ela. C# é fortemente tipada: o compilador recusa misturar coisas incompatíveis antes mesmo de rodar.

string nome    = "Yuri Alberto";   // texto (referência)
int    camisa  = 9;                // inteiro de 32 bits
double altura  = 1.82;             // ponto flutuante (aproximado)
decimal salario = 1250000.50m;     // dinheiro: precisão exata (sufixo m)
bool   titular = true;             // verdadeiro/falso
char   posicao = 'A';              // um único caractere
var    gols    = 17;               // o compilador deduz int

const int LIMITE_DE_GOLS = 100;    // constante: não muda nunca

// conversões
int textoParaNumero = int.Parse("10");
bool deuCerto = int.TryParse("dez", out int valor);   // não lança exceção

double media = (double)gols / 30;  // cast: evita divisão inteira

Console.WriteLine($"{nome} ({camisa}) tem {altura}m e {gols} gols.");
  • int, long, short, byte = inteiros de tamanhos diferentes.
  • double é rápido e aproximado; decimal é exato e usado para dinheiro. Nunca use double para valores financeiros.
  • var não significa "sem tipo": o tipo é fixado na atribuição e não muda depois.
  • Em C# o separador decimal é ponto. 1,82 não compila.
  • Tipos de valor (int, double, bool, struct) copiam o conteúdo; tipos de referência (string, classes) copiam o endereço do objeto.

03

Condições — vitória, empate ou derrota

if/else · switch · ternário · operadores

Programa é decisão. Com if você escolhe um caminho conforme uma condição booleana — e o C# exige que essa condição seja de fato bool (nada de "0 é falso" como em C).

int corinthians = 2;
int adversario  = 1;

if (corinthians > adversario)
{
    Console.WriteLine("Vitória! Três pontos no bolso.");
}
else if (corinthians == adversario)
{
    Console.WriteLine("Empate. Um ponto e muita reclamação da arbitragem.");
}
else
{
    Console.WriteLine("Derrota. Semana de silêncio no grupo.");
}

// operador ternário: if/else curto em uma linha
string clima = corinthians > adversario ? "festa" : "cobrança";

// switch em instrução
char resultado = 'V';
switch (resultado)
{
    case 'V': Console.WriteLine("3 pontos"); break;
    case 'E': Console.WriteLine("1 ponto");  break;
    case 'D': Console.WriteLine("0 ponto");  break;
    default:  Console.WriteLine("Rodada não jogada"); break;
}

// switch expression (mais moderno, devolve valor)
string premio = resultado switch
{
    'V' => "festa no vestiário",
    'E' => "quase lá",
    'D' => "reunião de emergência",
    _   => "sem jogo"
};
  • Igualdade é ==; um = só é atribuição.
  • Lógicos: && (e), || (ou), ! (não). Em cadeias longas, use parênteses para deixar claro.
  • && e || fazem curto-circuito: se o primeiro já decide, o segundo nem é avaliado.
  • switch expression devolve valor e o _ é o caso padrão.

Repetição e arrays — escalando os 11

for · while · do/while · foreach · break/continue

Quando algo se repete, você usa laço. for quando sabe quantas vezes, foreach para percorrer coleções, while enquanto a condição valer e do/while quando precisa rodar pelo menos uma vez.

string[] escalacao =
{
    "Hugo Souza", "Fagner", "Gil", "Cássio", "Fábio Santos",
    "Roni", "Renato Augusto", "Rodrigo Garro",
    "Yuri Alberto", "Róger Guedes", "Gustavo Mosquito"
};

for (int i = 0; i < escalacao.Length; i++)
{
    Console.WriteLine($"{i + 1}. {escalacao[i]}");
}

foreach (string jogador in escalacao)
{
    if (jogador == "Cássio") continue;   // pula este
    if (jogador == "Roni") break;        // encerra o laço
    Console.WriteLine(jogador);
}

int rodadas = 1;
while (rodadas <= 38)
{
    rodadas++;               // 38 rodadas de Brasileirão
}

// matriz: tabela com linhas e colunas
int[,] jogosPorMes = { { 4, 5 }, { 6, 4 } };
Console.WriteLine(jogosPorMes[0, 1]);   // 5
  • Índices começam em 0: o primeiro jogador é escalacao[0].
  • Length evita estourar o índice. Nunca escreva i <= Length.
  • break sai do laço; continue pula para a volta seguinte.
  • foreach não deixa alterar o item durante a iteração — para modificar, use for ou reconstrua a coleção.

05

Métodos e parâmetros

retorno · ref/out · opcionais · sobrecarga

Método é um bloco com nome que recebe dados (parâmetros) e devolve um resultado. Serve para não repetir cálculo e para dar nome às regras do jogo.

int Aproveitamento(int pontos, int jogos)
{
    if (jogos == 0) return 0;
    return pontos * 100 / (jogos * 3);   // % dos pontos possíveis
}

// expression-bodied: atalho para corpo de uma linha
string Situacao(int aprov) => aprov switch
{
    >= 70 => "brigando pelo título",
    >= 45 => "no meio da tabela",
    _      => "brigando embaixo"
};

// parâmetro opcional com valor padrão
void Anunciar(string time, string estadio = "Neo Química Arena") =>
    Console.WriteLine($"{time} joga na {estadio}");

// sobrecarga: mesmo nome, assinaturas diferentes
int Somar(int a, int b) => a + b;
double Somar(double a, double b) => a + b;

// out: devolve mais de um valor pelo parâmetro
bool TentarMarcar(int chance, out string narracao)
{
    if (chance > 50) { narracao = "GOOOL!"; return true; }
    narracao = "pra fora";
    return false;
}

int aprov = Aproveitamento(pontos: 61, jogos: 30);   // argumentos nomeados
TentarMarcar(70, out string grito);
  • return encerra o método e entrega o valor; métodos sem retorno usam void.
  • ref permite alterar a variável original; out serve para devolver um valor extra (o método é obrigado a atribuí-lo).
  • Sobrecarga = mesmo nome com parâmetros diferentes; o compilador escolhe pela assinatura.
  • Argumentos nomeados (pontos: 61) deixam a chamada legível e dispensam lembrar a ordem.

06

Classes, objetos e propriedades

construtor · get/set · static · this

Classe é o molde; objeto é cada jogador concreto criado a partir dele. É a base da orientação a objetos e o que você vai usar todo dia.

class Jogador
{
    // propriedade com validação no set
    private int gols;
    public int Gols
    {
        get => gols;
        set => gols = value < 0 ? 0 : value;
    }

    public string Nome   { get; set; }
    public int    Camisa { get; init; }      // só define na criação
    public bool   Titular { get; private set; } = true;

    public static int TotalCriados { get; private set; }  // pertence à classe

    public Jogador(string nome, int camisa)
    {
        Nome   = nome;
        Camisa = camisa;
        TotalCriados++;
    }

    public void MarcarGol() => Gols++;

    public string Resumo() => $"#{Camisa} {Nome} — {Gols} gols";
}

var garro = new Jogador("Rodrigo Garro", 10);
garro.MarcarGol();
garro.Gols = -5;                     // vira 0 pela validação
Console.WriteLine(garro.Resumo());
Console.WriteLine($"Jogadores criados: {Jogador.TotalCriados}");
  • { get; set; } é propriedade automática; get => ... / set => ... permitem lógica.
  • init deixa definir só no new; private set deixa ler de fora e alterar só por dentro.
  • static pertence à classe, não ao objeto — acessado como Jogador.TotalCriados.
  • O construtor tem o mesmo nome da classe e não declara retorno.
  • this é a referência ao próprio objeto (útil quando o parâmetro tem o mesmo nome do campo).

Listas e coleções básicas

List<T> · Add/Remove · Count · Sort

Array tem tamanho fixo. Para elenco que cresce na janela de transferências, use List<T> — ela cresce sozinha.

var elenco = new List<Jogador>
{
    new Jogador("Yuri Alberto", 9)  { Gols = 17 },
    new Jogador("Rodrigo Garro", 10) { Gols = 12 },
    new Jogador("Róger Guedes", 11)  { Gols = 15 }
};

elenco.Add(new Jogador("Memphis", 94));
elenco.RemoveAll(j => j.Gols == 0);

int totalGols = 0;
foreach (var j in elenco) totalGols += j.Gols;

// ordenar com comparação personalizada
elenco.Sort((a, b) => b.Gols.CompareTo(a.Gols));

Console.WriteLine($"Elenco: {elenco.Count} jogadores, {totalGols} gols.");
Console.WriteLine($"Média: {(double)totalGols / elenco.Count:F1} gols por jogador.");
Console.WriteLine($"Artilheiro: {elenco[0].Nome}");
  • List<Jogador> só aceita objetos do tipo Jogador — o compilador garante.
  • Count é o tamanho da lista; em array é Length.
  • {(double)...:F1} formata com uma casa decimal; o cast evita divisão inteira.
  • Sort recebe uma função de comparação: negativo = a antes, positivo = b antes.

LINQ — consultas de campeonato

Where · OrderBy · Select · GroupBy · Sum

LINQ transforma "percorrer e filtrar" em uma frase legível. Funciona em listas, arrays, XML, banco de dados (via EF Core) e qualquer coisa que implemente IEnumerable<T>.

var artilheiros = elenco
    .Where(j => j.Gols >= 12)
    .OrderByDescending(j => j.Gols)
    .Select(j => $"{j.Nome}: {j.Gols}")
    .ToList();

int golsDoTime = elenco.Sum(j => j.Gols);
var camisa10   = elenco.FirstOrDefault(j => j.Camisa == 10);
bool temArtilheiro = elenco.Any(j => j.Gols > 20);

var porPosicao = elenco
    .GroupBy(j => j.Posicao)
    .Select(g => new { Posicao = g.Key, Total = g.Count() });

Console.WriteLine($"Total do time: {golsDoTime}");
Console.WriteLine(camisa10 is null ? "Sem camisa 10!" : camisa10.Nome);
  • => dentro de LINQ é uma lambda: "para cada jogador j, faça isto".
  • Where filtra, OrderBy ordena, Select transforma, Sum soma, Any responde sim/não.
  • FirstOrDefault devolve null se não achar — trate sempre esse caso.
  • A consulta é preguiçosa (deferred): só executa quando você itera ou chama ToList/Count.
  • Precisa de using System.Linq; em projetos com using explícito.

Exceções — quando algo dá errado

try · catch · finally · throw · exceção personalizada

Nem tudo sai como o planejado: o arquivo não existe, o usuário digita "dez" onde era para digitar 10, o servidor cai. Em vez de retornar códigos de erro, o C# usa exceções: o problema sobe pela pilha de chamadas até alguém tratar. Se ninguém tratar, o programa encerra com um stack trace.

Exceções em C# são objetos. Toda exceção herda de System.Exception, e cada tipo carrega um significado: FormatException (texto em formato inválido), FileNotFoundException, NullReferenceException, DivideByZeroException, ArgumentException, InvalidOperationException.

int CalcularAproveitamento(int pontos, int jogos)
{
    if (jogos <= 0)
        throw new ArgumentException("Jogos deve ser maior que zero.", nameof(jogos));

    return pontos * 100 / (jogos * 3);
}

string LerPlacar(string entrada)
{
    try
    {
        int gols = int.Parse(entrada);          // pode lançar FormatException
        return $"Placar registrado: {gols} gols";
    }
    catch (FormatException ex)
    {
        // ex.Message explica; ex.StackTrace mostra o caminho
        return $"Não entendi o placar: {ex.Message}";
    }
    catch (OverflowException)
    {
        return "Número grande demais.";
    }
    finally
    {
        // roda sempre: deu certo, deu erro ou houve return
        Console.WriteLine("Tentativa de leitura encerrada.");
    }
}

// filtro de exceção (when): só trata em certas condições
try { CalcularAproveitamento(10, 0); }
catch (ArgumentException ex) when (ex.ParamName == "jogos")
{
    Console.WriteLine("Ajuste o número de jogos.");
}

// exceção personalizada, com dados do domínio
try
{
    throw new JogoCanceladoException("Clássico", "chuva forte");
}
catch (JogoCanceladoException ex)
{
    Console.WriteLine($"{ex.Message} Motivo: {ex.Motivo}");
}

class JogoCanceladoException : Exception
{
    public string Motivo { get; }

    public JogoCanceladoException(string jogo, string motivo)
        : base($"O jogo {jogo} foi cancelado.")
    {
        Motivo = motivo;
    }
}
  • try envolve o código perigoso; catch trata; finally sempre executa (fechar arquivo, liberar conexão).
  • Capture a exceção mais específica primeiro: FormatException antes de Exception.
  • throw cria o problema; throw; (sem objeto) relança preservando o stack trace original — nunca faça throw ex;.
  • Use nameof(x) para citar o parâmetro e ex.Message para a mensagem — mas não mostre stack trace cru ao usuário final.
  • Não engula exceções com catch { } vazio: você esconde o bug. Trate, registre (log) ou deixe subir.
  • Exceção é para o excepcional. Validação previsível (campo vazio, número inválido) costuma ser melhor com TryParse/bool de retorno.

Custo: lançar exceção é caro (captura o stack). Em laço de milhares de itens, prefira int.TryParse e validações a try/catch por item.

Arquivos e JSON — salvando o campeonato

File · Path · JsonSerializer · desserializar

Até aqui tudo vivia na memória: fechou o programa, perdeu o elenco. Para guardar dados de verdade, as duas ferramentas do dia a dia são arquivos (System.IO.File) e JSON (System.Text.Json, já embutido no .NET).

using System.Text.Json;

class Time
{
    public string Nome   { get; set; } = "";
    public int    Pontos { get; set; }
    public int    Jogos  { get; set; }
    public int    Saldo  { get; set; }
}

var tabela = new List<Time>
{
    new() { Nome = "Corinthians", Pontos = 61, Jogos = 30, Saldo = 18 },
    new() { Nome = "Palmeiras",   Pontos = 58, Jogos = 30, Saldo = 22 }
};

// monta caminho que funciona em Linux e Windows
string pasta = Path.Combine(
    Environment.GetFolderPath(Environment.SpecialFolder.MyDocuments), "Timao");
Directory.CreateDirectory(pasta);                 // não reclama se já existe
string caminho = Path.Combine(pasta, "tabela.json");

// ---------- gravar ----------
var opcoes = new JsonSerializerOptions
{
    WriteIndented = true,                          // JSON legível
    Encoder = System.Text.Encodings.Web.JavaScriptEncoder.UnsafeRelaxedJsonEscaping
};
string json = JsonSerializer.Serialize(tabela, opcoes);
File.WriteAllText(caminho, json);                  // sobrescreve / cria

// ---------- ler ----------
try
{
    if (File.Exists(caminho))
    {
        string conteudo = File.ReadAllText(caminho);
        var carregado = JsonSerializer.Deserialize<List<Time>>(conteudo);

        foreach (var t in carregado ?? new List<Time>())
            Console.WriteLine($"{t.Nome}: {t.Pontos} pts (saldo {t.Saldo})");
    }
}
catch (JsonException ex)
{
    Console.WriteLine($"JSON inválido: {ex.Message}");
}
catch (IOException ex)
{
    Console.WriteLine($"Falha de disco: {ex.Message}");
}

// acrescentar uma linha sem reescrever tudo
File.AppendAllText(caminho, Environment.NewLine + "// fim");
  • File.WriteAllText / ReadAllText resolvem 90% dos casos; AppendAllText acrescenta.
  • Path.Combine monta caminhos corretos no Linux e no Windows — nunca concatene com "/".
  • Nome de propriedade vira chave do JSON. Para renomear, use [JsonPropertyName("nome")].
  • Para Deserialize funcionar, a classe precisa de propriedades públicas com get/set (ou construtor compatível).
  • Sempre trate IOException (disco cheio, arquivo em uso) e JsonException (arquivo corrompido ou editado à mão).
  • JSON não guarda tipos: números viram double na desserialização — use int/long nas propriedades para o conversor ajustar.

Enums, structs, records e nullable

enum · record · struct · ? · ?? · pattern matching

Além de classes, o C# tem tipos feitos para casos específicos: enum para conjuntos fixos de opções, struct para valores pequenos, record para dados imutáveis com igualdade por conteúdo — e nullable para representar "pode não ter valor".

enum Posicao { Goleiro, Zagueiro, Lateral, Meia, Atacante }

// record: igualdade por valor, ToString pronto, imutável por padrão
record Jogador(string Nome, int Camisa, Posicao Posicao, int Gols = 0)
{
    public bool Artilheiro => Gols >= 15;
}

var g10 = new Jogador("Rodrigo Garro", 10, Posicao.Meia, 12);
var outro = g10 with { Gols = 18 };          // cópia alterando um campo
Console.WriteLine(g10 == outro);              // False: valores diferentes

// struct: tipo de valor, boa para dados pequenos
struct Coordenada
{
    public int X { get; init; }
    public int Y { get; init; }
}

// nullable: o "talvez" do C#
Jogador? camisa10 = null;
int? gols = null;

Console.WriteLine(camisa10?.Nome ?? "Nenhum camisa 10 definido");
Console.WriteLine(gols.HasValue ? gols.Value.ToString() : "sem dados");

// pattern matching
string Classificar(Jogador j) => j switch
{
    { Gols: >= 20 } => "artilheiro do campeonato",
    { Posicao: Posicao.Goleiro } => "defende o gol",
    { Gols: 0 } => "ainda não marcou",
    _ => "jogador comum"
};
  • enum dá nomes a números e impede valores fora da lista; por baixo, é um inteiro.
  • record compara por valor (não por referência) e o with cria cópia alterando campos.
  • struct é tipo de valor e vive na pilha: use para dados pequenos e curtos, como coordenadas. Struct grande copia muito e custa caro.
  • ? marca "pode ser null"; ?. só acessa se não for null; ?? dá o valor alternativo.
  • Nullable Reference Types (ligado por padrão em projetos novos) faz o compilador avisar sobre possíveis NullReferenceException.

Herança, interfaces e polimorfismo

abstract · virtual/override · interface · composição

Herança reaproveita comportamento: Jogador e ComissaoTecnica são Pessoa. Interfaces definem contratos: quem assina, promete implementar. Polimorfismo é a consequência: você chama o mesmo método e cada tipo responde do seu jeito.

abstract class Pessoa
{
    public string Nome { get; init; } = "";

    // método abstrato: cada filho é obrigado a implementar
    public abstract string Funcao();

    // virtual: tem implementação, pode ser sobrescrito
    public virtual string Apresentacao() => $"{Nome} — {Funcao()}";
}

interface IPagavel
{
    decimal Salario { get; }
    decimal CalcularPagamento(int meses);
}

class Jogador : Pessoa, IPagavel
{
    public int Camisa { get; init; }
    public decimal Salario { get; init; }

    public override string Funcao() => $"camisa {Camisa}";

    public override string Apresentacao() =>
        base.Apresentacao() + " (profissional)";

    public decimal CalcularPagamento(int meses) => Salario * meses;
}

class Tecnico : Pessoa, IPagavel
{
    public decimal Salario { get; init; }
    public override string Funcao() => "técnico";
    public decimal CalcularPagamento(int meses) => Salario * meses * 1.2m;
}

var elenco = new List<Pessoa>
{
    new Jogador { Nome = "Garro", Camisa = 10 },
    new Tecnico { Nome = "Dorival" }
};

foreach (var p in elenco)
    Console.WriteLine(p.Apresentacao());   // cada um responde do seu jeito

// polimorfismo via interface
foreach (var pagavel in elenco.OfType<IPagavel>())
    Console.WriteLine(pagavel.CalcularPagamento(12));
  • abstract não pode ser instanciado; serve de base obrigatória.
  • virtual permite sobrescrever; override faz a sobrescrita; base.Metodo() chama a versão do pai.
  • Uma classe herda de uma classe, mas implementa várias interfaces.
  • Prefira composição (um objeto tem outro) a herança profunda — herança é acoplamento forte.
  • Interfaces deixam o código testável: você troca a implementação real por uma falsa no teste.

Generics e coleções avançadas

T · constraints · Dictionary · HashSet · Queue · Stack

List<Jogador> já é generic: o <T> é o tipo que você escolhe. Com generics você escreve código uma vez e ele funciona para qualquer tipo, com verificação em tempo de compilação e sem conversões arriscadas.

// método genérico com restrição: T precisa ter construtor sem parâmetros
T CriarPadrao<T>() where T : new() => new T();

// classe genérica com duas restrições
class Repositorio<T> where T : class, IIdentificavel
{
    private readonly List<T> itens = new();
    public void Adicionar(T item) => itens.Add(item);
    public T? BuscarPorId(int id) => itens.FirstOrDefault(i => i.Id == id);
    public int Total => itens.Count;
}

interface IIdentificavel { int Id { get; } }

// ---------- coleções por caso de uso ----------

// Dictionary: busca por chave, O(1)
var golsPorJogador = new Dictionary<string, int>
{
    ["Yuri Alberto"] = 17,
    ["Garro"] = 12
};
golsPorJogador["Róger Guedes"] = 15;

if (golsPorJogador.TryGetValue("Garro", out int gols))
    Console.WriteLine($"Garro tem {gols} gols");

// HashSet: sem duplicatas, testa existência rápido
var convocados = new HashSet<string> { "Garro", "Yuri" };
convocados.Add("Garro");                // ignorado, já existe
bool estaNaLista = convocados.Contains("Yuri");

// Queue (fila) e Stack (pilha)
var fila = new Queue<string>();        // FIFO: primeiro a entrar, primeiro a sair
fila.Enqueue("entrevista");
fila.Enqueue("exame médico");
string proximo = fila.Dequeue();

var pilha = new Stack<string>();       // LIFO: último a entrar, primeiro a sair
pilha.Push("base");
pilha.Push("topo");
string topo = pilha.Pop();
  • <T> pode ser qualquer nome, mas T é a convenção.
  • Restrições (where): class, struct, new(), IInterface, notnull.
  • Dictionary = chave/valor; HashSet = conjunto único; Queue = fila; Stack = pilha.
  • Acessar dict[chaveInexistente] lança exceção; use TryGetValue ou GetValueOrDefault.
  • Escolher a coleção certa é metade da performance: busca por chave em lista é O(n), em dicionário é O(1).

Delegates, eventos e lambdas

Action · Func · event · callback

Delegate é uma variável que guarda um método. Com ela você passa comportamento como argumento — é o que LINQ, eventos de UI e Unity fazem o tempo todo.

// Action: método sem retorno | Func: método com retorno
Action<string> gritar = texto => Console.WriteLine(texto.ToUpper());
Func<int, int, int> soma = (a, b) => a + b;
Predicate<int> eGol = gols => gols > 0;

gritar("gooool");
Console.WriteLine(soma(2, 3));

// delegate nomeado (útil quando a assinatura se repete)
delegate bool FiltroJogador(Jogador j);

List<Jogador> Filtrar(List<Jogador> elenco, FiltroJogador filtro)
{
    var resultado = new List<Jogador>();
    foreach (var j in elenco)
        if (filtro(j)) resultado.Add(j);
    return resultado;
}

var artilheiros = Filtrar(elenco, j => j.Gols >= 15);

// evento: notificação de que algo aconteceu
class Partida
{
    public event Action<string>? GolMarcado;   // assinantes recebem o autor

    public void MarcarGol(string autor)
    {
        GolMarcado?.Invoke(autor);              // ?. evita erro sem assinantes
    }
}

var partida = new Partida();
partida.GolMarcado += autor => Console.WriteLine($"Gol de {autor}!");
partida.GolMarcado += autor => Console.WriteLine("Torcida explode.");
partida.MarcarGol("Garro");                     // chama os dois inscritos
  • Action<T> = recebe e não devolve; Func<...,TResult> = devolve; Predicate<T> = devolve bool.
  • += inscreve um handler no evento; -= remove (importante para não vazar memória).
  • Invoke dispara o delegate; ?.Invoke protege contra evento sem inscritos.
  • Lambdas capturam variáveis do escopo externo (closure) — cuidado ao capturar a variável de um laço.

Async, await e threads

Task · await · WhenAll · CancellationToken

Baixar dados da internet, ler um arquivo grande ou esperar um banco de dados são operações de espera. Se você bloqueia a thread, a tela congela. async/await deixa o programa seguir vivo enquanto espera — sem criar uma thread para cada espera.

using System.Net.Http;

// método async devolve Task (ou Task<T> quando devolve valor)
async Task<string> BuscarResultadoAsync(string time, CancellationToken ct)
{
    using var http = new HttpClient();

    // await libera a thread enquanto a resposta não chega
    string html = await http.GetStringAsync(
        $"https://api.exemplo.com/resultados/{time}", ct);

    return html.Length > 0 ? html : "sem dados";
}

// disparar várias tarefas ao mesmo tempo e esperar todas
try
{
    using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(10));

    var tarefas = new[]
    {
        BuscarResultadoAsync("corinthians", cts.Token),
        BuscarResultadoAsync("palmeiras", cts.Token)
    };

    string[] resultados = await Task.WhenAll(tarefas);
    Console.WriteLine(resultados.Length);
}
catch (TaskCanceledException)
{
    Console.WriteLine("Tempo esgotado.");   // cancelamento não é erro do programa
}

// trabalho pesado de CPU: sair da thread principal
int CalcularTabela() => Enumerable.Range(1, 1_000_000).Sum();
int total = await Task.Run(CalcularTabela);
  • async marca o método; await espera o resultado sem travar a thread.
  • Não use Thread.Sleep em código async — use await Task.Delay.
  • Task.WhenAll executa em paralelo e espera todas; WhenAny retorna na primeira que terminar.
  • CancellationToken é o jeito educado de desistir de algo demorado.
  • Async "sobe a pilha": se você chama um método async, seu método também deve ser async. Evite .Result e .Wait() — podem travar (deadlock).

Testes, garbage collector e boas práticas

xUnit · IDisposable · GC · dotnet CLI

Fechando os fundamentos: como provar que o código funciona, como liberar recursos e como não brigar com o garbage collector (o coletor de lixo que libera memória sozinho).

// ---------- TESTE AUTOMATIZADO (xUnit) ----------
// dotnet new xunit -o Timao.Tests  |  dotnet test
public class AproveitamentoTests
{
    [Fact]
    public void TresVitoriasEmTresJogos_Dao100PorCento()
    {
        int aprov = Calculadora.Aproveitamento(pontos: 9, jogos: 3);
        Assert.Equal(100, aprov);
    }

    [Theory]
    [InlineData(0, 0, 0)]
    [InlineData(6, 4, 50)]
    public void CasosVariados(int pontos, int jogos, int esperado)
    {
        Assert.Equal(esperado, Calculadora.Aproveitamento(pontos, jogos));
    }
}

// ---------- LIBERAR RECURSOS: using / IDisposable ----------
// using garante Dispose() mesmo se der exceção
using var arquivo = new StreamWriter("log.txt");
arquivo.WriteLine("fim de jogo");

class Conexao : IDisposable
{
    public void Dispose() => Console.WriteLine("conexão fechada");
}

// ---------- GC: o que importa na prática ----------
// 1. objetos são liberados sozinhos quando ninguém referencia
// 2. não chame GC.Collect() "para ajudar": piora a performance
// 3. recursos externos (arquivo, socket, conexão) precisam de Dispose
// 4. alocar dentro de laço quente gera pressão de memória
  • Teste automatizado prova o comportamento e evita regressão quando você mexe no código.
  • [Fact] é um caso; [Theory] com [InlineData] roda vários cenários.
  • using chama Dispose no fim do escopo — é o padrão para arquivos, streams e conexões.
  • O GC cuida de memória gerenciada; ele não fecha arquivos nem libera handles do sistema.
  • Nomes claros, métodos curtos, uma responsabilidade por classe — mais valioso que qualquer truque de linguagem.
